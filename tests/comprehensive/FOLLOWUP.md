# Follow-up validation

This campaign closes the deployment isolation gap, adds source-scored free answers, and completes genuine multi-day execution. Final results and raw evidence are in [the dated report](../../test-results/2026-10-16-followup/README.md). A prepared Docker lab is required; no host workspace or socket is mounted in model containers.

- project-config.mjs generates the actual isolated deployment exercised here. See [deployment instructions](../../integrations/openclaw-tdai-local/PROJECT-ISOLATION.md).
- holdout-cases.json contains 24 manually authored, distinct synthetic questions, including numerical/unit conversion, supersession, dated history, cross-project false matches, poisoned recall, missing facts, retraction, authorization and a known semantic retrieval gap. Labels were frozen before the run and never sent to the model. Baseline/policy receive identical real scoped MCP retrieval and Markdown evidence; six requests produce 48 scored answers. This is a public author-authored evaluation, not independent expert validation. No claim of statistical accuracy gain.
- holdout.mjs saves the manifest, corpus hash, actual retrieved rows, raw responses and per-answer exact value/status/citation scores. Missing or duplicate answers fail; invented citations fail. A legitimate citation explaining uncertainty can still fail this strict exact-citation metric; inspect raw results instead of treating every deduction as a wrong fact.
- disk-full.mjs fills only a dedicated bounded /probe tmpfs, asserts real ENOSPC and failed SQLite write, then frees its own filler and checks successful same-process recovery. It refuses another filesystem type.
- endurance.mjs runs inside each project's container, with copies of only the reviewed harness and MCP sources in its own state volume. --capture makes one paid actual Agent turn; --verify checks native own positives/peer negatives. Object files are synthetic sentinels, not generated profiles.
- --smoke runs 120 observed seconds with a forced Gateway process-group kill and MCP restart every 30 observed seconds. --run requires 72 real observed hours, forced recovery every six hours, and at days one and two one real Agent turn plus actual L0/L1 extraction. The proxy retains the previous cumulative ledger. No paid retry after an interrupted checkpoint.
- Every ten seconds the runner checks health/native retrieval/file isolation, exercises scoped MCP capture and retrieval, and checks authoritative-file hash stability. Integrity checks include SQLite and FTS orphan detection. Samples measure the whole container's cgroup memory. Planned recovery and gaps longer than 90 seconds do not count as healthy observed duration. A machine/daemon outage can extend the finishing time.
- Atomic progress checkpoints, raw turns, events and Gateway logs remain in the respective Docker volumes. Source hashes prevent silently replacing an active campaign. A terminal checkpoint waits for the operator monitor to archive results and stop the container.

Ordinary CI remains offline: unit checks, small retrieval benchmark, and the 10,000-record stress/recovery runner. The long campaign and paid model calls are opt-in and never run in pull request CI.
